# Ручная Проверка Двух Физических Устройств

## Назначение

Этот чеклист предназначен для завтрашнего debug-теста доставки между двумя
физическими Android-устройствами в одной Wi-Fi сети. Это проверка MVP, а не
подтверждение production security: активные чаты используют
`SimplifiedSessionManager`, Signal-backed sessions и `PARANOIA_C4_AEAD` выключены,
а LAN HTTP relay предназначен только для разработки.

## Перед Началом

На ноутбуке из каталога проекта:

```bash
cd android-app/server/relay
node --test
node src/server.mjs
```

Relay должен слушать `0.0.0.0:8787`. Проверьте его локально:

```bash
curl http://127.0.0.1:8787/health
```

На macOS обычно получить Wi-Fi IP можно так:

```bash
ipconfig getifaddr en0
```

Если адрес не найден, выполните `networksetup -listallhardwareports` и используйте
активный Wi-Fi интерфейс. Для IP `192.168.1.45` URL тестового relay будет
`http://192.168.1.45:8787`.

`127.0.0.1` на реальном телефоне означает сам телефон, а не ноутбук. Он подходит
только вместе с `adb reverse` для USB-теста одного устройства. Два телефона в Wi-Fi
должны использовать LAN IP ноутбука.

## Настройка Устройств

1. Установите одну debug APK на устройства A и B и создайте на каждом отдельный локальный профиль.
2. На обоих устройствах откройте `Настройки` -> `Сервер доставки`.
3. Введите один LAN URL ноутбука и сохраните его.
4. Убедитесь, что показано предупреждение о debug-only HTTP relay.
5. Нажмите `Проверить сервер доставки` и получите статус `Сервер доступен`.
6. Откройте `Диагностика доставки`: там должен появиться health status, но не текст сообщения и не полный queue ID.

## Двусторонний QR Pairing

1. A показывает своё приглашение в `Добавить контакт`; B сканирует и импортирует его.
2. B показывает своё приглашение; A сканирует и импортирует его.
3. На обоих устройствах откройте разговор и подтвердите, что выполнен импорт обоих QR-кодов.
4. Статус должен измениться с инструкции о втором QR-коде на `Готово к переписке.`
5. По доверенному каналу сравните контрольные коды безопасности и отметьте устройства проверенными.

Подтверждение взаимного QR в UI является записью о выполненном пользователем шаге,
а не автоматической криптографической аттестацией второго телефона.

## Доставка A -> B И B -> A

1. На A отправьте короткое тестовое сообщение B.
2. На B нажмите `Синхронизировать сейчас`, если fetch не выполнился автоматически.
3. Проверьте появление сообщения и событие `INCOMING_ACCEPTED` в диагностике B.
4. На B отправьте ответ A и повторите проверку на A.
5. В отчёте допустимы статусы, счётчики, время и значения вида `sha256:...`; полного queue ID, payload, nonce, ключей или ciphertext быть не должно.

## Retry После Остановки Relay

1. Остановите процесс relay на ноутбуке.
2. Отправьте новое тестовое сообщение.
3. В диагностике отправителя проверьте увеличение failed/retry count и событие `OUTGOING_RETRY_SCHEDULED`.
4. Снова запустите relay и проверьте `/health`.
5. Нажмите `Синхронизировать сейчас` на отправителе, затем на получателе.
6. Проверьте `OUTGOING_SENT`, `INCOMING_ACCEPTED` и уменьшение ожидающей очереди.

WorkManager выполняет best-effort синхронизацию; энергосбережение Android может
задержать её, поэтому ручная кнопка является контрольным действием QA.

## Duplicate Suppression

Для штатного ручного сценария relay удаляет принятое сообщение после durable local
save, поэтому дубль не должен появляться. Если тестовый harness повторно подаёт тот
же authenticated envelope, в UI не должно появиться второе plaintext-сообщение, а
журнал может показать `INCOMING_DUPLICATE_SUPPRESSED`. Не модифицируйте ciphertext
вручную для пользовательского теста.

## Блокировка Устройств

В разделе безопасности контакта проверьте следующие состояния:

- `Ожидает проверки`: отправка блокируется с причиной pending approval.
- `Отозвано`: отправка блокируется с причиной revoked.
- `Ключ изменён`: отправка блокируется с причиной key changed.
- Отсутствующее основное устройство: отправка блокируется с причиной missing primary device.

Ни одно новое или изменившееся устройство не должно получить автоматическое доверие.

## Если Тест Не Прошёл

Запишите без сообщения и без секретов:

- модель устройства и версию Android;
- версию debug APK/commit hash;
- Relay URL и время проверки `/health`;
- диагностический отчёт из приложения;
- направление доставки (A -> B или B -> A);
- видимые статусы pending/failed/next retry и technical event codes;
- был ли relay остановлен, перезапущен или недоступен через firewall.

Не прикладывайте тексты сообщений, QR invitation payload, ключи, nonce, полные
queue IDs или encrypted blob contents.
