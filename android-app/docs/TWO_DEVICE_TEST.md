# Проверка На Двух Устройствах

## Статус И Ограничения

Этот сценарий предназначен только для проверки MVP в локальной сети. Приложение
не готово для реальной чувствительной переписки: активные сессии всё ещё используют
prototype ECDH/HKDF вместо reviewed Signal/PQXDH/Double Ratchet, HTTP relay раскрывает
сетевые метаданные, а независимый аудит не выполнен. `PARANOIA_C4_AEAD` и
Signal-backed chats остаются выключенными.

## Запуск Relay На Ноутбуке

Требуется Node.js 20+:

```bash
cd android-app/server/relay
node --test
node src/server.mjs
```

Dev relay по умолчанию слушает `0.0.0.0:8787` и имеет health endpoint:

```bash
curl http://127.0.0.1:8787/health
```

Ожидаемый ответ: `{"status":"ok"}`. Relay хранит только opaque encrypted envelopes
с TTL и не должен журналировать тела сообщений, ciphertext envelopes, ключи,
nonce или queue identifiers.

## Как Узнать IP Mac

Если ноутбук подключён к Wi-Fi через стандартный интерфейс, выполните:

```bash
ipconfig getifaddr en0
```

Если команда ничего не вернула, найдите активный интерфейс:

```bash
networksetup -listallhardwareports
```

Затем используйте его вместо `en0`. Например, при результате `192.168.1.45`
адрес relay для физических телефонов будет:

```text
http://192.168.1.45:8787
```

Ноутбук и оба телефона должны быть в одной доверенной тестовой Wi-Fi сети.
Локальный firewall macOS должен разрешать входящие подключения Node к порту `8787`.

## Почему Не `127.0.0.1`

На физическом Android-устройстве `127.0.0.1` указывает на сам телефон, а не на
ноутбук. Для двух телефонов через Wi-Fi используйте LAN IP ноутбука. Эмулятор Android
может обращаться к хосту через значение по умолчанию `http://10.0.2.2:8787`.

USB-проверка одного телефона также может использовать:

```bash
adb reverse tcp:8787 tcp:8787
```

и адрес `http://127.0.0.1:8787`, но это не сценарий двух устройств по Wi-Fi.

## Настройка Двух Телефонов

1. Соберите и установите debug APK на оба тестовых Android-устройства:

   ```bash
   ./gradlew :app:assembleDebug
   adb -s <serial-A> install -r app/build/outputs/apk/debug/app-debug.apk
   adb -s <serial-B> install -r app/build/outputs/apk/debug/app-debug.apk
   ```

2. На каждом устройстве создайте отдельный локальный профиль.
3. На каждом устройстве откройте `Настройки` -> `Сервер доставки`.
4. Введите один и тот же LAN URL ноутбука, например `http://192.168.1.45:8787`,
   нажмите `Сохранить сервер`, затем `Проверить сервер доставки`.
5. Убедитесь, что на обоих устройствах показано `Сервер доступен`.

Debug-сборка разрешает пользовательский HTTP endpoint только для локальной
проверки. Release policy по-прежнему запрещает cleartext transport.

## Двусторонний QR Pairing

Приглашение содержит очередь получения владельца. Поэтому один QR-код не создаёт
двусторонний адрес автоматически:

1. На устройстве A откройте `Добавить контакт` и покажите QR-код.
2. На устройстве B отсканируйте QR-код A, задайте локальное имя A и импортируйте его.
3. На устройстве B откройте собственный QR-код приглашения.
4. На устройстве A отсканируйте QR-код B, задайте локальное имя B и импортируйте его.
5. На обоих устройствах сравните контрольный код безопасности по доверенному каналу
   и только затем явно отметьте контакт как проверенный.

Новые дополнительные устройства не получают доверие автоматически. Состояния
`Ожидает проверки`, `Ключ изменён` и `Отозвано` блокируют доставку на такое устройство.

## Проверка Сообщений И Retry

1. В переписке на A отправьте тестовое сообщение устройству B.
2. На B нажмите `Синхронизировать сейчас`, если сообщение ещё не появилось.
3. Проверьте статус `Получено` на B и отправьте ответ B -> A.
4. На A при необходимости нажмите `Синхронизировать сейчас` и проверьте ответ.

Для проверки retry:

1. Остановите relay на ноутбуке.
2. Отправьте новое тестовое сообщение. Оно останется в состоянии ошибки/ожидания
   с durable retry metadata в локальной базе.
3. Запустите relay снова.
4. Нажмите `Синхронизировать сейчас` или дождитесь WorkManager. После успешной
   отправки принимающее устройство сможет забрать сообщение.

WorkManager выполняет best-effort background sync и может быть задержан Android
из-за режима энергосбережения. Он повторно использует тот же delivery pipeline:
аутентификация выполняется до записи входящего сообщения, replay marker записывается
атомарно, а relay envelope удаляется только после принятия или распознавания
аутентифицированного дубля.

## Что Relay Всё Ещё Видит

- IP-адреса клиентов и время запросов;
- queue identifiers;
- размеры и частоту encrypted envelopes;
- факт использования одного relay двумя устройствами.

Relay может удалять, задерживать или подменять blobs; AEAD должна отвергать
подменённое содержимое, но не предотвращает отказ в обслуживании или анализ трафика.
